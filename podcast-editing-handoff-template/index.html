What the editor needs to know

Include one owner contact, the approved episode title, source location, raw duration, separate track names, intended final length if known, delivery deadline and any content timestamps that matter.

  • Use nonconfidential metadata for the first quote.
  • Agree on a secure upload before sending private recordings.
  • Identify one person authorized to approve revisions.

A copy-ready handoff structure

Paste the example into a note or email and replace placeholders with your actual instructions. It avoids giving a stranger store logins, social credentials or other unnecessary access.

WORKED EXAMPLE · ILLUSTRATIVE
SHOW / EPISODE:
SOURCE RECORDING TOOL:
RAW DURATION / FILE COUNT:
SPEAKER TRACKS:
CONTENT CUTS WITH TIMESTAMPS:
INTRO / OUTRO / MUSIC RIGHTS CONFIRMED:
REFERENCE EPISODE LINK:
WAV / MP3 DELIVERY SPECS:
TARGET DATE AND TIMEZONE:
REVISION APPROVER:
OTHER NONCONFIDENTIAL NOTES:

Separate blockers from preferences

Missing or damaged source files can block an edit; a preference about music fade timing can often be handled during the revision. Label each note as must-fix, optional or requires clarification.

Protect version history

Retain a copy of the accepted source, first delivery and final revision. Name the revision clearly so the editor and host do not publish the wrong version.

Attach a bounded paid pilot

If the source fits, the Podcast Audio Desk $99 pilot accepts up to 45 minutes of raw source audio across two tracks, one minor revision and a target four-business-day delivery. Bigger or damaged sessions need a separate scope.
